# Design — inclusionist-demos: one game per catalog item

**Date:** 2026-08-25 · **Status:** approved by the Dev · **Scope:** architectural

> [!note] Language of artifacts
> **English throughout** — documentation, code, comments and commit messages — matching the tracer
> and the rest of the constellation. The conversation with the Dev stays pt-BR.
>
> One deliberate exception: the **catalog page's own content** stays pt-BR. It is the product,
> written for a pt-BR audience; translating its 383 entries is a separate decision, not a
> side effect of this one.

## 1. Goal

`minigames-catalog-v2.html` lists 35 categories and **383 subgenres** of JS minigame. The goal is to
build a genuinely playable game for each item and wire the item to its game, reusing the stack and
conventions of `SP-the-inclusionist-tracer`.

At least 4 names appear in more than one card (`Snake roguelite`, `Auto-runner platformer`,
`Esgrima de timing`, `Spot the difference`), so the number of **unique** games is lower than 383 —
the manifest handles this with `aliasOf` instead of duplicating an implementation.

## 2. Decisions

| # | Decision | Rejected alternative |
|---|---|---|
| D1 | 383 games as the target, delivered card by card | 35 games (one per category); a curated subset |
| D2 | Inherit only the **technical core** from the tracer | Inherit a11y + i18n; inherit the 10 EdSP pillars |
| D3 | Monorepo with a shared engine | Self-contained games; engine as a package both repos consume |
| D4 | `jrocha-dev/inclusionist-demos`, **private** | Public; name it `js-minigames` |
| D5 | Pixel art on a **320×180** canvas (same as the tracer) | 360×180 — rejected: not 16:9, no integer scaling |
| D6 | SVG or 3D only when the game's nature demands it, with a recorded justification | Leave the renderer choice free per game |
| D7 | A single shell with dynamic imports | 383 entries in `rollupOptions.input` |
| D8 | Catalog **generated** from `data/catalog.json` | Hand-editing 383 `<li>` elements |

**D6 in practice:** `pixel` is the default. A game declaring another renderer fills in `rendererWhy`
in **its own `meta`** (the code is the source, not the manifest), and the build fails when a
non-`pixel` renderer arrives without one — the deviation stays auditable instead of becoming a habit.

## 3. Architecture

### 3.1 Layout

```
inclusionist-demos/
├─ index.html                  # GENERATED by scripts/build-catalog.mts — never hand-edited
├─ play.html                   # single shell hosting any game
├─ data/catalog.json           # source of truth for the catalog
├─ src/catalog.template.html   # today's hero, intro, changelog, CTA and CSS, preserved
├─ scripts/
│  ├─ import-catalog.mts       # one-shot: current HTML → catalog.json
│  └─ build-catalog.mts        # catalog.json + template → index.html
├─ engine/
│  ├─ core/      constants, loop, rng, collision, state
│  ├─ input/     keyboard, gamepad, state, latch
│  ├─ render/    canvas, palette, sprites, fx
│  ├─ platform/  audio, storage
│  └─ shell/     boot, router, hud, pause
└─ games/<category-slug>/<game-slug>/
   ├─ main.ts
   └─ main.test.ts
```

Slugs derive from the **name**, not the number (`games/arcade-classico/snake/`): reordering the
catalog then renames no folders and breaks no links.

### 3.2 Single shell and routing

`play.html` is the only build entry besides `index.html`. It discovers games through
`import.meta.glob('./games/*/*/main.ts')` and loads them on demand, routed by hash:

```
play.html#arcade-classico/snake
```

What this buys: one build entry instead of 383; PixiJS in a shared chunk; HUD, pause and
"back to catalog" born identical in every game; adding a game means creating a folder, with no
configuration to touch.

### 3.3 Game contract

```ts
export const meta: GameMeta;
export function setup(ctx: GameContext): void;
export function update(dt: number): void;   // dt is in FRAMES, not seconds
export function teardown(): void;
```

```ts
interface GameMeta {
  slug: string; title: string; category: string;
  density: 'leve' | 'medio' | 'denso';
  players: 1 | 2 | 3 | 4;
  renderer?: 'pixel' | 'svg' | '3d';        // defaults to 'pixel'
  rendererWhy?: string;                     // required when renderer !== 'pixel'
}
interface GameContext {
  stage: Container;                          // PixiJS root, 320×180 logical space
  input: InputApi;                           // held(pl, act), pressed(pl, act), players
  audio: AudioApi; rng: Rng; storage: StorageApi;
  onGameOver(score: number): void;
}
```

> [!warning] Two inherited conventions that are easy to break
> **`dt` is counted in frames, not seconds** — physics copied from a seconds-based tutorial runs wrong.
> **The keyboard is listened to on `#game-region`, not on `window`** — on `window` the game steals the
> page's keys.

### 3.4 Engine

Mirrors the tracer's split, with the modules rewritten for the scope here:

- **core** — `constants` (`LOGICAL_W=320, LOGICAL_H=180, TILE=16`), `loop` (RAF with frame-counted `dt`
  and a clamp against stalls), `rng` (seedable PRNG, so procedural games stay testable), `collision`
  (AABB and swept).
- **input** — the tracer's **8 actions** (`up, left, down, right, run, jump, swap, especial`),
  persisted `solo/p2/p3/p4` schemes, gamepad with `PAD_DEAD = 0.5`, and the unified query
  `held(pl, act) = keyboard OR gamepad`. `latch` supplies the edges (`pressed`/`released`).
- **render** — `canvas` sets up PixiJS with `NEAREST` and **integer scaling** (never fractional, which
  blurs pixel art); `palette`, procedural `sprites`, and `fx` (particles, screen shake).
- **platform** — `audio` (Web Audio, no asset files) and `storage` (high scores, remapped controls).
- **shell** — `boot`, `router`, `hud`, `pause`.

**Art is data**, as in the tracer: no PNG ships inside a game. Sprites come from procedural description.

## 4. Data-driven catalog

`data/catalog.json` is the source of truth:

```json
{ "version": "2.0.0",
  "categories": [{
    "id": 1, "slug": "arcade-classico", "title": "Arcade Clássico",
    "desc": "tela única · loop curto · score", "density": "leve", "accent": "c1", "new": false,
    "items": [
      { "slug": "snake", "name": "Snake / Cobrinha", "hint": "grid · auto-move · cresce",
        "fresh": false, "status": "todo" },
      { "slug": "snake-roguelite", "name": "Snake roguelite", "hint": "upgrades por morte",
        "fresh": true, "status": "todo", "aliasOf": "hibridos-mashups/snake-roguelite" }
    ]
  }]
}
```

(Item `name` and `hint` stay pt-BR — they are the page's visible content, per the language note above.)

`status` is `todo | wip | done`. Generation rules:

1. a `done` item becomes `<a href="play.html#<category>/<slug>">`; a `todo` item stays plain text —
   no 383 broken links, and the page turns into an honest progress meter;
2. an item with `aliasOf` (format `"<category>/<slug>"`) points at the existing game, is marked as a
   variation, and gets no folder of its own under `games/`;
3. the hero statistics become **computed**, which fixes today's stale "280+" (it is 383);
4. hero, intro, changelog, CTA, footer and all CSS come from the template, untouched.

`import-catalog.mts` runs once to extract the JSON from the current HTML, preserving name, hint,
the `fresh` marker, density, accent color and the `NEW` badge.

**Fate of the current file:** in Phase 1 `minigames-catalog-v2.html` is split — prose and CSS become
`src/catalog.template.html`, data becomes `data/catalog.json`, and the original leaves the root. The
generated `index.html` stays **self-contained and openable offline**, which is the one property of
the original that must survive. Git history preserves the original, and the commit that removes it
cites this section.

## 5. Testing

Vitest with the tracer's two projects: **node** (pure rules — game logic, collision, rng) and
**browser**/Playwright (render, input, shell). Every game is born with a rule test; TDD.

## 6. Phasing

| Phase | Delivery | Why |
|---|---|---|
| 0 | Repo, remote, this spec | — |
| 1 | Engine + `play.html` + **Snake, Pong, Breakout** + catalog generator + live links | They cover grid logic, two-player input, and continuous collision with FX — if the engine is wrong, these three expose it |
| 2 | Close card 01 entirely (17 items, all light) | First fully wired card; validates the per-category rhythm |
| 3+ | Card by card, ascending density | `denso` categories ship as a **vertical slice**, not a whole game |

## 7. Infrastructure

- Git on `main`; **frequent, atomic** commits, in English, no giant "initial".
- Remote: `jrocha-dev/inclusionist-demos`, private.
- **GPL-3.0-or-later**, with an SPDX header per file, as in the tracer.
- Node 24, TypeScript, Vite, Vitest, PixiJS 7.4.2 — the tracer's versions.
- No absolute paths in versioned files.

## 8. Non-goals (explicit YAGNI)

Out of scope by D2: i18n, WCAG 2.2 conformance sold as such, PWA/offline, xAPI telemetry,
LGPD/COPPA, networked multiplayer, level editor, backend.

Accessibility **hygiene still applies** (visible focus, reasonable contrast, no fast flashing, every
game playable from the keyboard alone) — what we skip is auditing and **claiming** conformance. The
distinction matters: the tracer marks honestly where it only reaches AA, and the worst outcome here
would be asserting a level nobody verified.

## 9. Risks

| Risk | Mitigation |
|---|---|
| 383 games is months of work and can die halfway | The catalog's progress meter makes advance visible; per-card delivery closes useful units |
| Silent fork: this engine drifting from the tracer's | If the two converge in practice, D3 is revisited and the engine becomes a package both consume |
| Build time growing with hundreds of chunks | The single shell already avoids 383 entries; if it hurts, group chunks by category |
| `denso` categories inflating scope | Explicit contract: a vertical slice (one room, one boss, one 60-second loop) |
