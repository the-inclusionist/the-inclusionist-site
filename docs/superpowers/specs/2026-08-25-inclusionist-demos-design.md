# Design — inclusionist-demos: one game per catalog item

**Date:** 2026-08-25 · **Status:** approved by the Dev · **Scope:** architectural

> [!note] Language of artifacts
> **English throughout** — documentation, code, comments and commit messages — matching the tracer
> and the rest of the constellation. The conversation with the Dev stays pt-BR.
>
> The **catalog page's own content** stays pt-BR for now. With i18n in the foundation (D2) making
> the page trilingual is no longer a mechanism problem, but translating its 383 entries is content
> work and remains a separate decision.

## 1. Goal

`minigames-catalog-v2.html` lists 35 categories and **383 subgenres** of JS minigame. The goal is to
build a genuinely playable game for each item and wire the item to its game, reusing the stack and
conventions of `SP-the-inclusionist-tracer`.

At least 4 names appear in more than one card (`Snake roguelite`, `Auto-runner platformer`,
`Esgrima de timing`, `Spot the difference`), so the number of **unique** games is lower than 383 —
the manifest handles this with `aliasOf` instead of duplicating an implementation.

## 2. Decisions

| # | Decision | Rejected alternative |
|---|---|---|
| D1 | 383 games as the target, delivered card by card | 35 games (one per category); a curated subset |
| D2 | Inherit the technical core **plus i18n, the accessibility shell and PWA**, lifted from the tracer as a library | Technical core only — reversed after reading the tracer (see §4) |
| D3 | Monorepo with a shared engine | Self-contained games; engine as a package both repos consume |
| D4 | `jrocha-dev/inclusionist-demos`, **private** | Public; name it `js-minigames` |
| D5 | Pixel art on a **320×180** canvas (same as the tracer) | 360×180 — rejected: not 16:9, no integer scaling |
| D6 | SVG or 3D only when the game's nature demands it, with a recorded justification | Leave the renderer choice free per game |
| D7 | A single shell with dynamic imports | 383 entries in `rollupOptions.input` |
| D8 | Catalog **generated** from `data/catalog.json` | Hand-editing 383 `<li>` elements |
| D9 | High contrast driven by a **role tag on every sprite**, resolved in the engine | Per-game color-blocking, as the tracer does it |
| D10 | **One i18n dictionary per game**, shipped with the game's chunk | One flat dictionary per locale, as the tracer does it |
| D11 | PWA precaches the shell and catalog only; game chunks are runtime-cached on demand | Precache everything, as the tracer does it |
| D12 | axe gate in CI over the DOM shell, with its blind spots stated | No gate; or claiming WCAG conformance in block |

**D6 in practice:** `pixel` is the default. A game declaring another renderer fills in `rendererWhy`
in **its own `meta`** (the code is the source, not the manifest), and the build fails when a
non-`pixel` renderer arrives without one — the deviation stays auditable instead of becoming a habit.

## 3. Architecture

### 3.1 Layout

```
inclusionist-demos/
├─ index.html                  # GENERATED by scripts/build-catalog.mts — never hand-edited
├─ play.html                   # single accessible shell hosting any game
├─ data/catalog.json           # source of truth for the catalog
├─ src/catalog.template.html   # today's hero, intro, changelog, CTA and CSS, preserved
├─ scripts/
│  ├─ import-catalog.mts       # one-shot: current HTML → catalog.json
│  ├─ build-catalog.mts        # catalog.json + template → index.html
│  └─ axe-check.mjs            # a11y gate, lifted from the tracer
├─ engine/
│  ├─ core/      constants, loop, rng, collision, state, i18n, a11y-sr
│  ├─ input/     keyboard, gamepad, state, latch
│  ├─ render/    canvas, palette, sprites, fx, high-contrast, cvd-matrices, viz-modes
│  ├─ platform/  audio, storage
│  └─ shell/     boot, router, hud, pause, a11y-regions
└─ games/<category-slug>/<game-slug>/
   ├─ main.ts
   ├─ strings.ts               # pt/en/es dictionary for this game only
   └─ main.test.ts
```

Slugs derive from the **name**, not the number (`games/arcade-classico/snake/`): reordering the
catalog then renames no folders and breaks no links.

### 3.2 Single shell and routing

`play.html` is the only build entry besides `index.html`. It discovers games through
`import.meta.glob('./games/*/*/main.ts')` and loads them on demand, routed by hash:

```
play.html#arcade-classico/snake
```

What this buys: one build entry instead of 383; PixiJS in a shared chunk; HUD, pause, the
accessibility regions and "back to catalog" born identical in every game; adding a game means
creating a folder, with no configuration to touch.

### 3.3 Game contract

```ts
export const meta: GameMeta;
export const strings: GameStrings;          // { pt: {…}, en: {…}, es: {…} }
export function setup(ctx: GameContext): void;
export function update(dt: number): void;   // dt is in FRAMES, not seconds
export function teardown(): void;
```

```ts
interface GameMeta {
  slug: string; title: string; category: string;
  density: 'leve' | 'medio' | 'denso';
  players: 1 | 2 | 3 | 4;
  renderer?: 'pixel' | 'svg' | '3d';        // defaults to 'pixel'
  rendererWhy?: string;                     // required when renderer !== 'pixel'
}
interface GameContext {
  stage: Container;                          // PixiJS root, 320×180 logical space
  input: InputApi;                           // held(pl, act), pressed(pl, act), players
  sprites: SpriteApi;                        // make({ role, … }) — see 3.5
  audio: AudioApi; rng: Rng; storage: StorageApi;
  t(key: string, params?: Record<string, string | number>): string;   // namespaced to this game
  srSay(text: string): void;                 // aria-live polite
  srAlert(text: string): void;               // aria-live assertive
  onGameOver(score: number): void;
}
```

> [!warning] Two inherited conventions that are easy to break
> **`dt` is counted in frames, not seconds** — physics copied from a seconds-based tutorial runs wrong.
> **The keyboard is listened to on `#game-region`, not on `window`** — on `window` the game steals the
> page's keys.

### 3.4 Engine

Mirrors the tracer's split, with the modules rewritten for the scope here:

- **core** — `constants` (`LOGICAL_W=320, LOGICAL_H=180, TILE=16`), `loop` (RAF with frame-counted `dt`
  and a clamp against stalls), `rng` (seedable PRNG, so procedural games stay testable), `collision`
  (AABB and swept), plus `i18n` and `a11y-sr` lifted from the tracer (§4).
- **input** — the tracer's **8 actions** (`up, left, down, right, run, jump, swap, especial`),
  persisted `solo/p2/p3/p4` schemes, gamepad with `PAD_DEAD = 0.5`, and the unified query
  `held(pl, act) = keyboard OR gamepad`. `latch` supplies the edges (`pressed`/`released`).
- **render** — `canvas` sets up PixiJS with `NEAREST` and **integer scaling** (never fractional, which
  blurs pixel art); `palette`, procedural `sprites`, `fx` (particles, screen shake), and the visual
  accessibility pass (§3.5).
- **platform** — `audio` (Web Audio, no asset files) and `storage` (high scores, remapped controls).
- **shell** — `boot`, `router`, `hud`, `pause`, `a11y-regions`.

**Art is data**, as in the tracer: no PNG ships inside a game. Sprites come from procedural description.

### 3.5 Visual accessibility: role tags instead of per-game code

Every sprite is created with a **semantic role**:

```ts
type SpriteRole = 'player' | 'ally' | 'hazard' | 'goal' | 'pickup' | 'bg' | 'ui' | 'neutral';
ctx.sprites.make({ role: 'hazard', /* … */ });
```

The engine's high-contrast pass recolors by role at the three contrast levels of the tracer's
ADR-0011 (3:1 / 4.5:1 / 7:1). **No game writes high-contrast code** — it declares what each thing
*means* and the engine does the rest.

This inverts the tracer's approach for a reason that only holds here: the tracer retrofits contrast
onto a finished platformer, so its color-blocking is bolted to a fixed four-role taxonomy with grid
bounds injected at init. We create every sprite through one factory on greenfield code, so the tag
is free at the point of creation. It is the single change that keeps one-game-per-prompt viable —
without it, high contrast would be bespoke work in all 383 games.

CVD simulation/correction and low-vision modes apply as filters to the **canvas element**, at shell
level, and cost a game nothing.

## 4. What is lifted from the tracer

Measured by `wc -l` against `SP-the-inclusionist-tracer` on 2026-08-25.

| Module | Lines | Disposition |
|---|---|---|
| `core/i18n.ts` | 90 | copied, then extended (D10) |
| `platform/storage.ts` | 63 | copied verbatim (i18n's only dependency) |
| `core/a11y-sr.ts` | 16 | copied verbatim |
| `ui/dom.ts` | 17 | copied verbatim (a11y-sr's only dependency) |
| `render/cvd-matrices.ts` | 97 | copied verbatim (pure data) |
| `render/viz-modes.ts` | 64 | copied verbatim (pure data) |
| `scripts/axe-check.mjs` | 53 | copied, retargeted at our shell |
| PWA block in `vite.config.ts` | ~30 | copied, caching strategy changed (D11) |

**Roughly 350 lines cross over with no rewrite.** The i18n mechanism is the surprise: `t()` with a
chained fallback, lazy per-locale loading via `import.meta.glob`, and `applyDom` for `[data-i18n]`,
depending on nothing but `storage`. i18n was originally cut from scope on the assumption it was
expensive; reading it reversed D2.

**Not lifted:** `render/high-contrast.ts` (217), `render/viz-setters.ts` (284) and
`render/hc-role-data.ts` (33) — 534 lines welded to the Inclusionist's own entity taxonomy, with
pieces (`_lastSharedViz`, `_pupTexHC`, `_playerDirect`) still living in its `game.js`. Replaced by
the role-tag pass of §3.5.

### 4.1 The three modifications

**D10 — per-game dictionaries.** The tracer keeps one flat file per locale (342/311/312 lines). At
383 games that file becomes unmanageable and every visitor downloads every game's strings. Instead
each game exports `strings`, registered under its slug when its chunk loads; `ctx.t` is pre-namespaced,
so a game calls `t('gameOver')` and never sees the prefix.

**Canvas text is not covered by `applyDom`**, which only walks `[data-i18n]` in the DOM. Text drawn
on the canvas needs `t()` at draw time and a redraw on the `i18n:change` event. The engine subscribes
once and calls a game's redraw, so the discipline is enforced in one place rather than 383.

**D11 — runtime caching.** The tracer's `globPatterns: ['**/*.{js,css,html,…}']` precaches everything,
correct for one game and wrong for 383: opening Snake would download the whole collection. The shell,
the catalog and the engine chunk are precached; game chunks are cached on first play.

## 5. Data-driven catalog

`data/catalog.json` is the source of truth:

```json
{ "version": "2.0.0",
  "categories": [{
    "id": 1, "slug": "arcade-classico", "title": "Arcade Clássico",
    "desc": "tela única · loop curto · score", "density": "leve", "accent": "c1", "new": false,
    "items": [
      { "slug": "snake", "name": "Snake / Cobrinha", "hint": "grid · auto-move · cresce",
        "fresh": false, "status": "todo" },
      { "slug": "snake-roguelite", "name": "Snake roguelite", "hint": "upgrades por morte",
        "fresh": true, "status": "todo", "aliasOf": "hibridos-mashups/snake-roguelite" }
    ]
  }]
}
```

(Item `name` and `hint` stay pt-BR — they are the page's visible content, per the language note above.)

`status` is `todo | wip | done`. Generation rules:

1. a `done` item becomes `<a href="play.html#<category>/<slug>">`; a `todo` item stays plain text —
   no 383 broken links, and the page turns into an honest progress meter;
2. an item with `aliasOf` (format `"<category>/<slug>"`) points at the existing game, is marked as a
   variation, and gets no folder of its own under `games/`;
3. the hero statistics become **computed**, which fixes today's stale "280+" (it is 383);
4. hero, intro, changelog, CTA, footer and all CSS come from the template, untouched.

`import-catalog.mts` runs once to extract the JSON from the current HTML, preserving name, hint,
the `fresh` marker, density, accent color and the `NEW` badge.

**Fate of the current file:** in Phase 1 `minigames-catalog-v2.html` is split — prose and CSS become
`src/catalog.template.html`, data becomes `data/catalog.json`, and the original leaves the root. The
generated `index.html` stays **self-contained and openable offline**, which is the one property of
the original that must survive. Git history preserves the original, and the commit that removes it
cites this section.

## 6. Testing and gates

Vitest with the tracer's two projects: **node** (pure rules — game logic, collision, rng) and
**browser**/Playwright (render, input, shell). Every game is born with a rule test; TDD.

`scripts/axe-check.mjs` runs in CI against the built shell (`play.html`) and the catalog
(`index.html`), failing on any WCAG A/AA violation. **What the gate does not reach**, stated here so
nobody mistakes a green run for conformance: axe cannot scan inside the canvas, so art contrast,
flash cadence and the legibility of in-game text are outside it. Those stay human judgment, and the
project claims exactly that — a passing DOM gate, not WCAG 2.2 conformance in block.

## 7. Phasing

**Phase 1 is deliberately heavy.** Every item below is written once and inherited by 382 games;
retrofitting i18n or accessibility across a finished collection would be the worst possible outcome.

| Phase | Delivery | Why |
|---|---|---|
| 1 | The foundation, below | One expensive phase buys 382 cheap games |
| 2 | Close card 01 entirely (17 items, all light) | First fully wired card; validates the per-category rhythm |
| 3+ | Card by card, ascending density | `denso` categories ship as a **vertical slice**, not a whole game |

Phase 1, in build order:

1. **Engine** — core, input, render, platform.
2. **Accessible shell** (`play.html`) — skip link, `#sr-status` / `#sr-alert` live regions,
   `role="application"` on `#game-region`, pause dialog with `aria-modal`, playable from the keyboard
   alone. Written once; axe scans this, not the canvas.
3. **i18n** — lifted mechanism plus per-game dictionaries (D10). Floor of three languages: pt-BR, en, es.
4. **Visual accessibility** — CVD and low-vision filters on the canvas element; high contrast by
   sprite role in the engine (§3.5).
5. **PWA** — precache shell, catalog and engine; runtime-cache game chunks (D11).
6. **axe gate in CI** (D12).
7. **Catalog generator** — `import-catalog.mts` once, then `build-catalog.mts`; links go live.
8. **Three reference games** — **Snake, Pong, Breakout**. They cover grid logic, two-player input, and
   continuous collision with FX. They are inside Phase 1 on purpose: the phase cannot be called done
   without three games proving the foundation works.

**Estimated per-game overhead once the foundation exists** — an estimate, not a measurement, since no
game has been written on this engine yet: a ~15-key dictionary in three languages, one role tag per
sprite, and 5–10 `srSay()` calls at the events that matter. Call it 30–50 lines on top of the game.
That fits in a single prompt. What would break the estimate: a game whose HUD is text-heavy, or one
whose entities do not map onto the eight roles.

## 8. Infrastructure

- Git on `main`; **frequent, atomic** commits, in English, no giant "initial".
- Remote: `jrocha-dev/inclusionist-demos`, private.
- **GPL-3.0-or-later**, with an SPDX header per file, as in the tracer.
- Node 24, TypeScript, Vite, Vitest, PixiJS 7.4.2 — the tracer's versions.
- No absolute paths in versioned files.

## 9. Non-goals (explicit YAGNI)

Out of scope: xAPI telemetry, LGPD/COPPA compliance, networked multiplayer, level editor, backend,
Libras/VLibras interpretation, neural TTS.

i18n, the accessibility shell and PWA **left this list** when D2 was reversed. What stays out of the
accessibility scope is the *claim*: we run the axe gate and say precisely what it covers (§6). The
tracer marks honestly where it only reaches AA, and the worst outcome here would be asserting a level
nobody verified.

## 10. Risks

| Risk | Mitigation |
|---|---|
| 383 games is months of work and can die halfway | The catalog's progress meter makes advance visible; per-card delivery closes useful units |
| Phase 1 grew large and could stall before any game exists | The three reference games are *inside* Phase 1 — it cannot be declared done without them |
| en/es translations nobody on the team can verify | Keep per-game strings few and plain; flag the debt rather than presenting the translations as reviewed |
| Green axe run read as WCAG conformance | §6 states the blind spots in the spec, and every accessibility claim repeats the scope |
| A game whose entities do not fit the eight sprite roles | `neutral` is the escape hatch; a second such game is the signal to revisit the taxonomy, not to special-case |
| Silent fork: this engine drifting from the tracer's | If the two converge in practice, D3 is revisited and the engine becomes a package both consume |
| Build time growing with hundreds of chunks | The single shell already avoids 383 entries; if it hurts, group chunks by category |
| `denso` categories inflating scope | Explicit contract: a vertical slice (one room, one boss, one 60-second loop) |
